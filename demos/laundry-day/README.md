# 晴天洗衣计划

把颜色、天气和赴约时间排成刚刚好的一天。一个可反复优化的生活策略小实验，不连接真实设备，也不需要账户。

## 核心玩法

- 从 6 件衣物中选择同色的一批，安排洗涤程序、开洗时刻、干燥方式和开始干燥时刻。
- 洗衣机与烘干机各一台；洗衣机承重 5 kg、烘干机 4 kg，自然晾衣位 6 个。洗涤与晾晒可以并行，两个洗涤批次却不能重叠。
- 节能洗 2 小时 / 1 点电；快洗 1 小时 / 3 点电；轻柔洗 2 小时 / 2 点电。羊毛必须轻柔洗且不能烘干。
- 自然晾晒累计 3 点即可收衣：晴 +2，阴 +1，雨归零。烘干花 4 点电，只需 1 小时。可以洗完后等天气窗口再晾。
- 试跑立即计算整天，不需要现实等待。逐小时查看日志，找到机器冲突、被雨重新打湿和迟到原因，再通过提前/延后或重排改善方案。
- 三个独立场景有不同天气、截止时间和节电目标；全部按时完成后比较星级和用电纪录。

支持撤销/重做、场景分别保存、重排批次及键盘操作。刷新后恢复计划；当前选择、撤销历史与试跑结果不持久化。

## 本地运行

Node.js 18 或更高版本。无第三方依赖、无需 API key。

```sh
cd demos/laundry-day
npm ci
npm test
npm run build
npm start
```

打开 `http://localhost:4173`。用 `PORT=4180 npm start` 修改端口。

`npm run build` 将入口与 `src/` 复制至独立 `dist/`。不要直接用 `file://` 打开 ES 模块。每个 demo 独立安装、测试和部署，无根目录 workspace。

## 测试

`npm test` 使用 Node 内置 `node:test`。27 项测试包括三个场景的完整成功策略、不同星级、雨淋进度清零、机器冲突、串色/羊毛规则、时间边界、存量不变性等。实现完成时 27/27 通过，build 与 JS 语法检查通过。

这些是引擎单元测试，不等于浏览器验证。浏览器实测记录由发布阶段补充到 `QA.md`，其中应区分实际通过与未测试内容。

## 部署

静态产物目录：`dist/`。无服务端，无外部资源加载、CDN、分析脚本或字体服务。可以部署到任意支持静态文件与 JavaScript ES 模块的 HTTPS 主机。已验证在线链接由发布协调阶段写入仓库导航和交付记录。

## 隐私与边界

数据只保存在访问者浏览器的 localStorage（键 `hakuya-laundry-v1`）；不上传、不发送请求、不收集私人信息。自行清除站点数据可移除存档。示例衣物、耗电、天气和规则都是游戏抽象，不是现实洗护建议。
