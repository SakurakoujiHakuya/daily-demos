# 传闻小镇

一个完全虚构的邻里消息传播策略游戏。查阅两份适用的来源、选择更正投递的节点，观察消息沿街巷扩散。三期拥有不同网络拓扑和一次预告的脱离语境转述；14步内达成至少6人依据已明、编辑部可信度≥50，才能完成本期目标。

## 运行

需要 Node.js ≥18。无第三方运行或开发依赖，各项目独立。

```sh
npm ci
npm test
npm run build
npm start
```

访问 http://localhost:4176 。可用 `PORT=其他端口 npm start` 更改端口。`dist/` 为静态部署产物，任意支持 JS module 的静态托管均可部署；Sites 的正式链接和源码发布记录由仓库目录维护。

## 核心操作

1. 在「来源核验台」查阅文件，每份消耗1步。旧剪报和缺少上下文的便条不能支持当下结论。
2. 点击地图圆点选居民。附依据更正让本人达到100、邻居+65，同时消耗1份纸墨；无依据的安慰影响较小且损害编辑部可信度。
3. 每一步结束，居民状态向邻居平均值靠近12%。每期有一次提前标明的转述事件，令一个节点−65。
4. 撤回会恢复完整资源。留底滑杆可回看历史状态，回看期间不会接受新的行动。「推演至截稿」会立即模拟剩余步数，不要求现实等待或反复点击。
5. 三期分别本地保存。重复探索不同落点、事件前后的发信时机、纸墨用量。切换期刊会恢复该期进度，重新开局只重置当前期。

## 设计边界

人物、事件、地点均为原创虚构。不采集网络、联系人、真实舆情或个人信息，不访问外部 API。数值仅是游戏规则，不能用于预测真实人的心理或认知。现实核查需要评估来源独立性、时间、上下文和证据质量；两个来源并不自动意味着真实。本作不是事实核查工具。

状态值：≥35依据已明，≤−35相信传闻，中间为观望。编辑部可信度是玩家行动资源，不是对居民的人格评分。得分=依据已明人数×10+可信度/5+剩余纸墨×2，不代表科学评估。

## 文件

- `src/engine.js`：纯函数状态机、三场景、传播/事件/撤回/保存重建。
- `src/app.js`：SVG网络、投递台、来源核验、回放、本地保存。
- `test/engine.test.js`：37项 Node 内置测试，含全部场景胜负对照、边界、撤回、事件与保存。
- `scripts/build.mjs`、`scripts/serve.mjs`：独立静态打包和预览。

## 部署

执行 `npm run build` 后将 `dist/` 托管；不需要服务器密钥、账号或数据库。正式 Sites 由协调任务按其源仓库与归档流程发布。无图片或字体的外部 CDN 依赖。
