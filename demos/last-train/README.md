# 末班车调度室 / Last Train Dispatch

一个可以重排时间、反复推演的中文公共交通策略小游戏。虚构城市、原创 SVG 地图，无真实出行数据、联网请求、外部素材、账号、API 或密钥。适配桌面和手机，原生 HTML/CSS/JavaScript，无运行时或开发依赖。

## 启动、测试与构建

需要 Node.js 20 或更新版本。

```sh
npm ci
npm test
npm run build
npm start
# 浏览器访问 http://localhost:4173
# 部署产物本地预览：node server.mjs --dist
# 自定义端口：PORT=4180 npm start
```

将 `dist/` 整个目录上传至任何静态托管即可，所有资源使用相对路径，可部署到子目录。不要直接双击 HTML（浏览器的 ES Module 安全策略需要 HTTP）。

## 核心玩法

- 3 个人工关卡：一次换乘接力、容量竞争、双向换乘。另有可复制种子的确定性随机挑战。
- 每关有限列车，每列选方向、发车分钟、沿途停站、星桥额外候车 0–5 分钟（跳过星桥时不可设置）。
- 轨道每段 1 分钟，中途停站增加 1 分钟；跳站节省时间但无法服务该站。
- 换乘需 1 分钟。有限座位、候车时间与到达期限共同制约计划。
- 同一轨道段双向共用，每分钟最多通过一列，编号小的先行。站台不设容量限制。
- 单步、暂停自动演练、直接结算均可。不强制等待，不依赖计时器判定结果。
- 地图呈现候车人数与每车载客数；清单呈现准点、迟到与在途人数；无线电记录解释换乘、上车和让行。
- 每次结算保留内存内的得分与完整方案，可恢复比较。刷新页面会清空记录。

## 得分与解题

准点抵达 +100 分，迟到抵达 +35 分，轨道让行每分钟 −3 分。截止分钟到达仍算准点。夜班结束时的候车和在途乘客不得分。手工关卡都有全员准点解，内置“参考方案”可验证，允许继续修改。随机题不保证全员送达。

单位乘客拥有独立状态：等待 → 在车上 → 换乘等待 → 抵达。同一分钟先处理所有列车到达，再上车，再分配轨道；换乘可用时间为下车分钟 +1。队列按候车可用时间、客流清单顺序排序，列车按编号上客/分配轨道。终点不继续载客。未开始候车的人仍计入“仍在候车”总量，但地图只显示已经到站的人；星桥数字后的 + 表示有人仍在步行换乘。

`engine.js` 是不依赖 DOM 的纯模拟引擎。`step` 返回深拷贝，不修改输入。`run` 快速结算；输入发车、停站、车数、候车时间均有校验。`test/engine.test.js` 覆盖容量溢出、错过发车、准点边界、迟到、跳站、轨道互斥、换乘步行、状态守恒、重置、种子复现与人工关卡可解性。

## 无障碍

原生按钮、数值输入与选择器；键盘焦点可见；停站按钮有按下状态；地图提供动态文本替代；支持减少动态效果。颜色以外同时使用线路名、编号、文字状态。主要操作在窄屏重新排列。

## 已知边界

这是分钟粒度的策略模型，不是铁路安全或真实运行图系统。站台容量无限，轨道冲突以编号优先解决。车辆走完整条预设方向，无法折返；不会动态重新寻路或改乘不同路线。自动播放仅用于展示。对比记录不持久保存。
