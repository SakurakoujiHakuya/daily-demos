# 花束之间 · Market Bouquet

有限的花材，无限的心意。一个原创中文花市创作 / 库存分配游戏，而不是花艺建议、真实交易或植物养护工具。

## 快速运行

需要 Node.js 18+，**零运行时或开发依赖**，无需安装第三方包。

```sh
npm test       # 30 项 Node 内置测试
npm run build  # 将四个静态文件复制至 dist/
npm start      # http://localhost:4173，PORT 可覆盖端口
```

也可将 `dist/` 发布到任意静态托管；ES 模块需要 HTTP 服务，不能通过 `file://` 直接运行。MIT 许可。所有插画都是仓库内原创程序化 SVG，不使用字体 CDN、分析 SDK 或外部图片。

## 这不是只点选标签的花束生成器

- **三摊市场 / 九张委托**：晨光小集、雨后长街、黄昏的礼物。每摊三张委托同时进行，共用 24 枝有限花材，每种仅 4 枝。
- 每枝花有独立身份、长度、颜色、花形与花材点。每束五个花位决定左右排列；换位、跨委托调配都会改变画面与库存。
- **真正的剪裁取舍**：只能剪短至 24 cm，取下不恢复原长；剪错可撤销。长花要留给尖塔中央，过早剪短会影响后续委托。
- **六项确定性评分**：花量 20、配色 20、轮廓 20、至少两种花形 15、左右平衡 15、花材点预算 10。所有得分即时显示，不隐藏抽卡概率。
- **剪余再利用**：每 15 cm 剪余制作一份虚构装饰，换回一枚补货零钱。零钱与每束花材点预算分开；每摊最多补货四枝。没有真实价格或支付。
- 满五枝即可交付，不要求满分。交付锁定花束；撤销交付后可继续改动。
- **自由花台**不评分；可以不放满，随时导出内嵌所有形状的独立 SVG。
- 自动保存每摊进度到此浏览器的 `localStorage`。无账号、无上传、无服务器存储。撤销保留当前场景本次会话最近 100 步；切换场景或刷新后不保留撤销栈。
- 手机 / 桌面响应式；按钮、滑杆均可键盘操作；有焦点状态、中文标签、实时提示与减弱动态效果支持。

## 操作

1. 读三份委托，给每份预留合适花色与高度。
2. 在左侧选一种花，点击中央花位放入。重复点同种花可轮选库存中同类花材。
3. 点击花束下的小标签，选择已经安放的一枝；拖动长度滑杆后确认剪短，或点「按目标剪」。虚线与花位数字显示理想轮廓。
4. 选花后点已占用花位会交换位置；跨委托也可交换。取下的花回到共用库存，但仍保持剪后长度。
5. 查看右侧分项分数。保留自己的非满分构图也是一种有效解法。
6. 交付后切换另一份委托；三份交付显示本摊结果。导出 SVG 不带辅助轮廓线。

## 文件与测试

- `engine.js`：纯函数状态迁移、评分、存档验证、SVG 渲染；无 DOM 依赖。
- `app.js`：真实 DOM 操作、撤销栈、各场景本地存档与 SVG 导出。
- `index.html` / `style.css`：中文界面与原创花台视觉系统。
- `test/engine.test.js`：30 项测试覆盖库存唯一性、纯函数、位置与跨单交换、不可逆剪裁、下限、回收、补货限制、交付锁定、不同策略结果、三套完整解法、替代解法、SVG 和存档校验。
- `scripts/build.js` / `scripts/serve.js`：仅用 Node 标准库。

`deployment-info.json` 记录本次公共发布身份、精确源码提交与 QA 证据，不包含令牌或凭证。部署工作区与本目录分开，源码目录不包含 Sites 身份配置或 Git 凭证。

## 数据与边界

所有客人、花名、花材点与预算都是虚构设定。无真实花店推荐、价格、保鲜、种植或专业花艺主张。没有任何后端调用；仅自主下载 SVG 时使用浏览器 Blob URL。删除站点本地存储即可清除所有游戏进度。
